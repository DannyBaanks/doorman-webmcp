      How it works

      An illustration of the sequence. These are not receipts from this session.

      1. add_item — allowed, executed
      2. update_item — denied, item not created by this agent session
      3. request_approval — allowed, waiting on a human decision
      4. A human approves one deletion — delete_item becomes available for that item only
      5. delete_item — allowed once, then the grant is consumed and the tool is unregistered

      Doorman is not a security boundary. This page’s own JavaScript could bypass it, and a hostile page is out of scope. It is an observable authority boundary: a pattern for cooperative agents and a window for the human watching. Receipts are an audit log for you, not evidence for anyone else.
