      How it works

      An illustration of the sequence. These are not receipts from this session.

      1. add_item Allowed The agent may use it freely, and every use leaves a receipt.
      2. update_item Conditional Allowed only on items the agent created in this session. Anything else comes back Denied.
      3. request_approval Allowed It can only ask. It never approves anything and never deletes.
      4. A human approves one deletion Granted once delete_item appears on the agent surface, valid for that one item.
      5. delete_item Grant consumed It runs once, then the tool is unregistered and reads Unavailable again.

      Doorman is not a security boundary. This page’s own JavaScript could bypass it, and a hostile page is out of scope. It is an observable authority boundary: a pattern for cooperative agents and a window for the human watching. Receipts are an audit log for you, not evidence for anyone else.
